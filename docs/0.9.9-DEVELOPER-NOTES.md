# 0.9.9 — developer notes

A day of field testing on the Windows laptop, 2026-09-23, with real phones and
no internet or router nearby. Each section: what was wrong, how it was found,
what changed, and where. Written for whoever works on this next, the Linux
side included; the code comments at each change carry the same reasoning at
the place it applies.

The rule that held all day: **measure the thing, then change it, then measure
again.** Several bugs below had passed their own tests.

---

## 1. Stop did not stop (tui.rs, serve.rs, dns.rs, dhcp.rs)

**Found by reading the code** after testers reported `gorilla.local` landing on
"previous instances".

- `forget_session` in `tui.rs` never raised `cable_stop`, so the beacon, the
  mDNS responder, the address handout and the name server ran until the
  process exited. A second start added a second set.
- The web server kept serving after Stop, and Stop reset the tick list to
  `None`, which `is_allowed` reads as *everything*: the whole previous folder,
  unticked files included.

**Changed:** `forget_session` raises the flag and calls `serve::halt()`. A
managed accept loop (`accept_loop(.., managed: true)`) checks `HALTED` and
`CURRENT_ROOT` through `gate()`; starting again reuses the bound listeners with
the new folder instead of failing to bind. Test: `halt_tests`.

## 2. The address handout never looked again (dhcp.rs `supervise`)

It checked `safe_to_offer` only while waiting. Once started it ran forever, so
a laptop that rejoined a routed network kept handing out addresses there: the
0.9.0 fault. Now it checks every 3 s; the handout and name server have their
own stop flag and stop the moment the guard says no, and start again when it
is clear.

## 3. `gorilla.local` (dns.rs)

- It was answered only in cable mode. It is now answered on the hotspot too,
  through `start_mdns_when_ready`, which waits for the hotspot's address.
- The responder answered every interface with the cable address and sent its
  group replies out of the default interface. Now: `same_link` filters askers
  to our own network, `IP_MULTICAST_IF` is set in `shared_udp`, and it
  announces on start and sends a ttl-0 goodbye on stop (`mdns_record`).
- `hub-captive.conf` (Linux) also maps `gorilla` and `gorilla.local`.

## 4. The Windows hotspot is switched on by the hub (net.rs)

**Measured first**, as an ordinary user: WinRT
`NetworkOperatorTetheringManager` switched Mobile Hotspot on in 314 ms, read
and set its name and password, and started from the *unplugged Ethernet*
profile with no internet.

- `WIN_HOTSPOT` is a PowerShell script run with `-EncodedCommand`; name,
  password and band travel in environment variables, never on a command line.
  Actions: `read`, `start`, `stop`, `channel`. WinRT from Rust directly would
  need a crate or a great deal of COM; PowerShell is on every Windows 10/11.
- `start` switches the wifi radio on first (`Windows.Devices.Radios`, allowed
  without admin, measured), configures only what differs, then starts.
- `hotspot_address_of`: counts only when the route to 192.168.137.1 *is*
  192.168.137.1. For about four seconds after a start the question answered
  with the other network's address, and `gorilla.local` was started there.
- After a start it waits for the address to hold for 1.5 s: renaming makes
  Windows switch off and on, and the old address lingers.

## 5. The band: 2.4 GHz (net.rs)

Two phones saw nothing while Windows reported the hotspot On. Measured with
`WlanQueryInterface` (opcode 8, channel) on the hotspot's own adapter,
laptop joined to no network (`bench/hotspot-channel-test.ps1`):

```
band Auto  -> channel 149 (5 GHz)   phones saw nothing
band 2.4   -> channel 6   (2.4 GHz)
```

The script sets the band to 2.4 GHz unless `HUB_BAND=5` (the start screen's
"Wifi band" row, or `hub serve --band 5`). Windows' hotspot API takes a band,
not a channel, so Windows picks the channel; the screen shows the measured one
(`measure_channel`, the `channel` action). This card also reports: no GO on
6 GHz, one GO port, 0 MLO connections (`wifi_card_summary`, shown on the fix
screen and in `hub doctor`).

## 6. Keeping it up (net.rs `guard_hotspot`)

Windows switches the hotspot off itself when the last device leaves with no
internet behind it, and switching the laptop's wifi off kills it. The guard
checks the address every few seconds and restarts it, radio included.
`HOTSPOT_OP` serialises start and stop so the guard can never restart the
network just after a Stop.

A 40-second outage was traced to the guard itself: it waited ten seconds for
the address after every attempt, refused ones included. The Windows side takes
half a second (`bench/hotspot-restart-timing.ps1`). Now it waits only when the
start was accepted and retries every 2 s. `bench/hotspot-guard-test.ps1`:
switched off from outside, back in 1.9 s; wifi radio off, back in 9.0 s.

Every outage and Windows' answer to each attempt goes to
`%LOCALAPPDATA%\PortableNetworkHub\network.log` (`network_log`).

## 7. Closing with X leaves nothing broadcasting (net.rs `arm_watchman`)

The X ends the process without running any of its code. `arm_restore` on
Windows starts a windowless PowerShell "watchman" (own hidden console, own
process group, out of the terminal's job where allowed) that waits for the hub
to end, however it ends, and stops the hotspot: the Windows twin of the Linux
systemd timer. `disarm_restore` sends it home on a clean stop.
`bench/hotspot-close-test.ps1`: killed, off after 6.7 s; window closed, off
after 6.5 s.

## 8. The sign-in page opens by itself on Windows (dns.rs `start_hotspot_names`)

A phone joined, and `gorilla.local` typed into its browser did nothing: the
name resolved, but the browser took it for a search. Windows' hotspot answers
DNS with its own proxy on 0.0.0.0:53; a socket bound to 192.168.137.1:53
exactly is allowed and receives the hotspot's questions first (measured). The
hub answers the phones' connectivity probes and its own names
(`PROBE_NAMES`, `OUR_NAMES`, `LOCAL_NAMES`) with its address, so the sign-in
page pops up; the web server already redirects foreign hosts. Other names go
to the router read from the route table (`route_gateway`; the old `.1` guess
was `.74` on the test day), or get `SERVFAIL` at once when there is none.

## 9. The QR codes could not be scanned (qr.rs `place_format`)

A phone would not scan them; OpenCV refused both. The 15-bit format field was
placed least significant bit first; the standard reads it most significant
first. Every code the program ever drew named the wrong mask and level. The
round-trip test read it back in the same wrong order and passed. Fixed, and a
new test checks the field against the standard's table written out as
constants: `the_format_field_reads_as_the_standard_says`. Verified with OpenCV
after the fix, border 2 and 4. The border on the sending screen is now two
modules, to fit a phone's camera frame.

## 10. Windows services switched off by tweak lists (services.rs)

`hub services` / "Turn on the parts of Windows the hub needs": reads the
registry `Start` values (numbers, any language), follows `DependOnService`
from the registry rather than a hand list, records the before-state to
`services-before.txt`, and with one UAC prompt (`ShellExecuteExW` "runas",
waiting for the child) raises what is off to Windows' own setting and starts
it. Success is decided by reading the registry again, not by the elevated
copy's word. `--put-back` restores the record. Only the person's action
launches the elevated copy, which never launches anything (tune.rs records a
self-elevation loop that filled a desktop with prompts).

The first screen checks in the background and says THIS COMPUTER IS NOT READY
when something is off; choosing wifi or cable stops at an offer to fix it.

## 11. Lists (grid.rs, term.rs, tui.rs)

The tick list was one column cut at 32 characters and did not scroll.
`grid.rs` lays items out in as many columns as fit (28 to 60 wide), cuts names
in the middle (`truncate_middle`), follows the cursor, and says in words how to
see the rest; `term.rs` now decodes Page Up/Down, Home and End. The tick
screen shows one folder at a time with file counts and `[x]/[~]/[ ]`; space on
a folder of 20+ files or 100 MB+ asks first with the number. A test walks every
key and checks the cursor is never off screen.

## 12. Received work (page.rs, serve.rs, tui.rs)

It went into `handed-in/` inside whatever folder was shared, which nobody
could find. `page::set_receive_dir` points it at
`Documents\Gorilla Hub received` (changeable from the start screen with the
folder picker); the sending screen shows it and `o` opens it (`open_with_system`;
the old code ran `xdg-open`, which Windows does not have). On the phone page,
chosen files are listed with REMOVE (a small script using `DataTransfer`),
picking again adds, and START AGAIN is a plain reset button. On the waiting
screen `e` accepts everything and `p` everything from one person.

## 13. Smaller things

- `build.rs` puts the date of the last commit next to the version on the first
  screen and in `--version`: every test build was 0.9.9 and a new one looked
  old. The commit date keeps builds reproducible.
- A panic hook writes `crash.log`: `panic = "abort"` plus Windows Error
  Reporting switched off by a tweak list meant a crash left no trace.
- `hub doctor` no longer sends Windows users to Settings, reads the gateway
  from the route table, calls wifi wifi, and does not claim "NO" for a missing
  firewall rule.
- A phone browser in desktop mode is labelled "Linux, or a phone in desktop
  mode" rather than "a Linux laptop".
- Tests touching the process-wide received folder take `SESSION_LOCK`.

## For the Linux side

Shared code (Stop, the codes, lists, received folder, accept all, mDNS
changes) applies to Linux too and is covered by tests there, but the Linux
hotspot paths have not been run on hardware since these changes. The handover
lists what to try.
