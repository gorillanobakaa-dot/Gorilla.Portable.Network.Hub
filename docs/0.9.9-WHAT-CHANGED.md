# 0.9.9, in plain language

**On Windows the hub now makes its own wifi network, and phones can find it,
join it by scanning a code, and land on the page without typing anything.**

Everything below was found by using the hub with real phones on a laptop far
from any town: no internet, no router, just the laptop and the phones. Most of
it was broken in ways no test had caught.

---

## The wifi network

**It switches itself on.** Before, a teacher had to find Settings, Network and
internet, Mobile hotspot, and switch it on by hand. Now choosing "Hand out
files over wifi" does it. No administrator password, and it works with no
internet at all.

**It is on a band every phone can see.** Left to itself, Windows put the
network on 5 GHz (channel 149), and two phones of different makes saw
nothing at all while Windows said the network was on. The hub now uses
2.4 GHz unless you choose 5 GHz on the start screen. The screen says which
channel it is really broadcasting on, read from the wifi card.

**It stays on.** Windows switches its hotspot off by itself when the last phone
leaves, and switching the laptop's wifi off kills it too. The hub now notices
within seconds and switches it back on, and says so on the screen while it
does. Closing the hub's window with the X, or a crash, now switches the network
off again instead of leaving it broadcasting.

## Getting phones onto it

**The codes work.** Every scan code this program had ever drawn, on Windows and
on Linux, was unreadable: one small part of it was written backwards. Checked
with an independent code reader, fixed, and checked again. Scan the first code
and the phone joins the network, password and all.

**The page opens by itself.** When a phone joins, it quietly asks "is there
internet?". The hub now answers that question, so the phone shows "Sign in to
network" and opens the lesson page. Nobody types an address.

## Laptops that have been "sped up"

Old laptops very often have parts of Windows switched off by a tweak list or a
script, and nothing looks wrong until the wifi network fails in front of a
class. The first screen now checks, and if something the hub needs is off it
says so plainly and offers to switch it back on, with one permission prompt.
"Check this computer" is now "Fix problems with this computer (wifi, cable,
firewall)", and it says what the laptop's wifi card can and cannot do.

## Files

**Choosing what to hand out.** The list uses the whole window in columns, pages
through long folders, and shows one folder at a time. Ticking a folder with
thousands of files in it asks first, with the number.

**On the phone, a chosen file can be taken back.** Picked files are listed with
a REMOVE button each, picking again adds more, and START AGAIN clears the lot.

**Received work goes to one place you can find:** Documents, "Gorilla Hub
received". The screen shows it, and the o key opens it. It used to go into a
hidden-away folder inside whatever you were sharing.

**Accept it all at once.** Forty children sending six pieces each was 240 key
presses. Now e accepts everything waiting, and p everything from one person.

## Smaller things

- Stop now really stops: the page, the name answering and the address handout
  all end with it, and a stopped lesson can no longer show the old folder.
- The first screen shows when the build was made, so an old copy cannot be
  mistaken for a new one.
- If the hub ever crashes, it writes down where, in a file.
- The health check (`hub doctor`) no longer says things that stopped being true.

## Not changed

Linux behaves as before apart from the shared fixes (the codes, Stop, the
lists, the received folder). No Linux packages come with this release: the
Linux hotspot changes have not yet been tried on a Linux laptop.
