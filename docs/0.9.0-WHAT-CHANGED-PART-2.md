# Making the cable usable by a person, and the bugs that only showed up when one used it — Plain Language

## What happened

The cable itself already worked. Forty-five megabytes had moved between the Windows laptop and the Debian laptop over an ordinary network cable, as one archive and as separate files, with folders inside folders arriving intact. What did not work was everything a person has to do around that: choosing what to send, understanding what the screen was telling them, and getting the other computer to find this one without being told a string of numbers.

This stretch of work was driven entirely by the owner using the tool as a person instead of testing it as a developer. That turned out to matter more than any test I could write. Five separate faults were reported, and my own automated checks had missed every one of them, because they all belonged to a category a program cannot check for itself: things that worked and gave no sign of having worked, and things that reported a state which had been true a minute ago and was not true any more.

The largest of them took three attempts to fix properly. The tool refuses to hand out network addresses when the computer is also connected to a real network, because two things handing out addresses on one office or school network can knock everybody on it offline. The owner turned the wireless off, exactly as the screen asked, and the screen carried on saying the same sentence. The reason turned out to be three separate stale readings stacked on top of each other, and fixing the first two was not enough.

## Honest state of play

Proven, by running it unattended with the wireless genuinely switched off and writing the result to a log file: the address handout starts by itself about five seconds after the wireless goes off; the name service answers; gorilla.local resolves to this computer; the page opens under that name; the sign-in probe that a Linux desktop makes gets the answer that should trigger its prompt; and the Debian laptop on the other end of the cable answers and can load the page. Ninety-eight automated checks pass.

Not proven, and I want to be exact about this. The forty-five megabyte transfer has not been repeated since these repairs. It was proven earlier on an earlier version, and the part of the program that actually moves the bytes has not been touched since, but that is an argument and not a measurement.

The Linux program file has still never been run. Not once, anywhere. It is built and structurally correct and nobody has executed it.

The sign-in prompt appearing by itself on the Debian screen has never been seen by anyone. Every piece it depends on now works when tested from the Windows side, but whether the Debian desktop then offers the prompt is something only a person sitting at that laptop can observe.

And nobody has typed gorilla.local on the Debian box since the new name service was added. The owner typed it once and it worked, but on a version where the name was answered a different way.

## Worst case if something is wrong

The thing worth watching is the address handout running somewhere it should not. If it hands out addresses on a school or office network that already has its own equipment, it competes with that equipment and can take every computer in the building off the network, not only the two involved in a transfer.

That is why it refuses by default and only acts when it can see it is on a bare cable. During this work I nearly made that worse: my first repair for the stale-reading problem would have removed the protection for a computer that is plugged into a live network but has not been given an address yet, which is exactly the computer that must not be interfered with. The automated check that caught it was already in the file, written earlier for that reason. If it had not been there I would have shipped it.

The practical worst case now is narrower: a computer plugged into a live network, in the few seconds before that network gives it an address, with the cable feature deliberately started at that moment. The tool no longer relies on there being an address; it looks for whether a router has actually spoken to the machine. That closes most of the window and not all of it.

## Glossary

**Address** — The number a computer needs before it can talk to any other computer, like a house number on a street.

**Handing out addresses** — Telling another computer what its number should be. A home router does this. On a bare cable there is no router, so this tool does it instead.

**Router** — The box that normally organises a network and connects it to the internet.

**Stale reading** — A piece of information that was true when it was collected and is no longer true. The main fault in this work was three of these on top of each other.

**gorilla.local** — A name that works on a local cable or network without anything being set up, the same way printers announce themselves.

**Neighbour table** — A short list a computer keeps of the machines it has recently spoken to. Used here to tell a real router from a leftover memory of one.

**Link-local address** — An address starting 169.254 that a computer gives itself when nothing else will. Seeing one is a reliable sign there is no router present.
