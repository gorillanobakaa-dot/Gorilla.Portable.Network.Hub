# 0.9.6, in plain language

One thing changed. It is small, and it was telling people something untrue.

---

## The program said this computer had no wifi

If you typed `hub doctor` on a Windows laptop, one of the lines it printed was:

```
wifi adapter   none found, so this computer cannot make a network
```

It said that on **every** Windows laptop. Always. Including the one this was
found on, which at that exact moment was connected to a wifi network, over a
perfectly healthy Intel wifi card, at 173 megabits a second.

It had not looked and failed to find anything. It had never looked at all. The
part of the program that checks for a wifi card is written for Linux, and on
Windows it is simply left out — so the "none found" branch was not the result
of a search. It was a fixed sentence that got printed no matter what.

### Why that mattered more than it sounds

The *conclusion* was right. This program cannot switch your wifi card into a
network by itself on Windows. That part is true.

But the *reason* it gave was false, and a wrong reason is worse than no reason,
because of what somebody does next. Read that line as a teacher and you go
looking for a broken wifi card, or a missing driver, or a laptop that is too
old. You might give up on the whole thing. And the card was fine the entire
time.

Worse, the program contradicted itself. If you actually tried to hand out files
over wifi, it told you the truth: *switch the hotspot on in Settings first, then
come back*. So one screen said "your laptop can't do this" and another said
"here's how to do it". Whichever you read first is the one you believed.

### What it says now

```
wifi adapter   this program cannot turn one into a network by itself here
               to hand out over wifi, switch the hotspot on first:
               Settings, Network and internet, Mobile hotspot
               then come back and start handing out
```

True, useful, and it agrees with the other screen.

It also does not claim to have checked your wifi card, because it still does
not. That is deliberate. Windows *can* be asked, but it answers in whatever
language the laptop was set up in, and this program is meant to work in Kabul
and Bamako as much as anywhere. Guessing at translated words is how you get a
new bug. And the advice is the same either way — so there is nothing to gain by
asking.

---

## Does this change anything on Linux?

**No. Nothing at all.**

The sentence that was wrong only ever appeared on systems that are not Linux.
A Linux machine running 0.9.5 is not missing anything, and does not need to
update.

## How this was found

Not by a test. The test suite passed, and would have gone on passing forever,
because nothing in it runs `doctor` and reads what comes out.

It was found by someone typing `hub doctor` on a real Windows laptop and
reading the screen — which is how nearly every real bug in this project has
been found. There is now a test guarding it, so it cannot come back quietly.

That is the whole release.
