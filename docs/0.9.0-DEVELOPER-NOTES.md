# hub 0.9.0: direct-cable transfer, embedded DHCP and link-rate tuning merged into the 0.8.0 tree

> Session record generated 2026-09-06

---

## Problem Being Solved

The tool could only move files over an existing wifi network. A direct CAT cable between two laptops is faster, immune to RF congestion and costs nothing, but has no router, and a router supplies two things the tool depended on: an address on each host, and a way for one host to locate the other. Windows, macOS and the BSDs self-assign RFC 3927 link-local addresses after DHCP times out at 30-60s; most Linux distributions default to 'Automatic (DHCP)' and block indefinitely, so the interface never comes up. A Windows-to-Debian cable transfer therefore failed with a connection timeout and no diagnostic.

A second, larger problem was the state of the code the new capability arrived in. It had been delivered as a from-scratch rewrite labelled 0.8.1: 2,734 lines replacing 0.8.0's 10,118, dropping qr.rs (780), tui.rs (2,166), term.rs (521) and dns.rs (297) without disclosure in its changelog. Those modules implement the QR join, the interactive dashboard, the terminal layer and reverse-name lookup, all of which the public 0.8.0 release advertises with screenshots. The rewrite had also reintroduced two defects 0.8.0 had already fixed.

## Approach Taken

Invert the merge direction. Take 0.8.0's tree as the base and port the ~800 lines of genuinely new capability into it as three new modules, instead of adopting the rewrite and re-adding what it deleted. This preserves qr/tui/term/dns and, critically, preserves serve.rs's existing safe_join() and clamped body reads, so the two reintroduced security defects never enter the codebase at all instead of being fixed a second time.

Each ported module was repaired during the port and not afterwards: the beacon's lossy name encoding, the DHCP module's absent lease table and unguarded interface binding, and the tuner's per-request subprocess spawn. New behaviour was surfaced through the existing TUI state machine and not through a parallel interface, on the explicit ground that the audience cannot be asked to drive a multi-subcommand CLI.

## Before

src/hub/src at 0.8.0: 12 modules, one `hub` binary, subcommands serve/get/sums/screen/doctor. serve.rs used a fixed 256 KB BUF for file streaming and called set_nodelay inline at accept. tui.rs presented a two-item home menu. net.rs contained two ungated tests calling #[cfg(target_os = "linux")] functions, so the test binary did not compile on Windows or macOS.

## After

15 modules, same single binary, subcommands serve/cable/cable-get/get/sums/screen/doctor/fix-firewall. serve.rs streams files in tune::wire().chunk-sized blocks (128 KB to 4 MB by negotiated link speed) while keeping the fixed 256 KB response-writer buffer, and calls tune::tune_socket on the accept path. tui.rs presents a four-item home menu with a cable mode that suppresses the wifi fields and a Checkup screen that opens firewall ports. 70 tests pass on Windows, including 12 new ones. Windows binary 700,416 bytes; a statically linked x86-64 musl Linux binary of 858,160 bytes has been produced and structurally verified but not executed.

## Known Alternatives

Two alternatives were considered and rejected against the owner's stated requirement that the capabilities 'complement each other' inside one download. Shipping the rewrite as 0.9.0 was rejected because it would silently remove the roster, QR join, TUI and mDNS that the release page advertises, and would ship weaker security than what is already public. Shipping the rewrite as a second `hub-cable` binary was rejected because it doubles the maintenance surface and splits the audience across two downloads. Within dhcp.rs, re-aliasing the host IP onto a conventional DHCP pool was rejected in favour of deriving the pool from the address the host already holds: quoting the source, 'Changing the host's own IP to suit a DHCP pool means touching system network configuration, which needs administrator rights, breaks whatever else was using that interface, and has to be undone afterwards, including after a crash.'

## Decisions Made

- 📄 **Base the merge on 0.8.0 and port the new modules in, instead of adopting the 0.8.1 rewrite** — The rewrite deleted 3,764 lines implementing advertised features and reintroduced a path traversal and an unbounded allocation that 0.8.0 had already fixed with safe_join() and len.min(64 * 1024).
- 📄 **Key DHCP leases on the client MAC instead of deriving the address from the server's own** — 'The original computed the client's address as a pure function of the server's own address... every client that ever asked received the identical IP. With one laptop on a cable this is invisible. With two it is an address conflict.'
- 📄 **Treat a link-local default gateway as no gateway in safe_to_offer()** — 'net::default_gateway() on Windows and Mac does not read the routing table; it guesses ".1 of whatever subnet we are on"... On a bare cable that guess comes back as 169.254.x.1, so the guard refused on exactly the machines the feature exists for.' RFC 3927 forbids forwarding link-local traffic, so such an address cannot be a router.
- 📄 **Cache the link-speed probe in a OnceLock** — 'The original called detect_hardware_profile() from inside the file-sending loop, and on Windows that function starts a PowerShell process. Every download by every device paid a PowerShell cold start to save a few milliseconds of copying.'
- 📄 **Cut the DHCP lease from 24 hours to 1** — 'A day-long lease handed out over a cable at nine in the morning is still held at four in the afternoon, in a different room, plugged into the real school network, where that address is wrong and nothing works.'
- 📄 **Make open_ports() return Result instead of printing** — 'the screen owns the whole terminal and anything printed to stdout is drawn over by the next frame a quarter of a second later.' The CLI wrapper prints; the TUI routes the same string into note().
- 📄 **Tab-delimit the beacon instead of substituting underscores for spaces** — 'a folder genuinely called "Year_7_Maths" arrived as "Year 7 Maths". Names belonging to other people are not ours to rewrite.'
- 🤖 **Author commits under the repository's existing placeholder identity** — Every one of the eight most recent commits is authored 'Your GitHub Username <your-email@example.com>'. Using the owner's real address would newly publish it to a public git history.

## Tried and Abandoned

- **cargo install cargo-zigbuild to cross-compile the Linux target** — The rustup toolchain on this machine is x86_64-pc-windows-msvc and Visual C++ Build Tools are not installed, so cargo-zigbuild's proc-macro build scripts (proc-macro2, quote, serde, thiserror) failed to compile. Replaced by invoking zig cc directly as the target linker, which works because this crate has no build scripts, no proc-macros and no C dependencies.
- **Linking the musl target with rustc's bundled self-contained CRT** — ld.lld reported duplicate symbols _start and _start_c between zig's crt1.o and rustc's self-contained rcrt1.o. Resolved with -C link-self-contained=no so zig supplies the CRT alone.
- **Calling term::leave()/term::enter() around the firewall fix in the TUI** — No such public API exists. term::Raw is an RAII guard whose Drop restores the terminal, with no way to suspend and resume it. Replaced by returning a Result from open_ports() and displaying it in the existing note() screen.
- **Building cable_get's download URL as format!("http://{ip}:{port}{}", fetch::url_path(name))** — url_path() escapes the name but does not prepend a slash, producing 'http://169.254.1.1:8080lesson.pdf'. Found by checking how tui.rs builds the same URL; a leading slash was added.

## ⚠ Claimed But Not Verified

*Prior documents claimed these are done. No test evidence found in this diff:*

- That the end-to-end cable transfer works with this build. The parts are unit-tested and the design is unchanged from the version that demonstrably worked, but no folder has been moved down a real cable using this binary.
- That the Linux binary runs. It has been confirmed to be a 64-bit little-endian x86-64 ELF of type EXEC with no dynamic loader string, but it has not been executed, because the build host is Windows.
- That the 169.254 addressing path behaves correctly on Linux as the sender. Binding UDP 67 requires root there; the code detects PermissionDenied and returns Refused::NeedsAdministrator, but this has not been exercised.
- Upstream's own documented claim of Windows XP SP3 and OS X 10.6 support. Rust 1.70+ supports neither target; this predates the current work and was not addressed.

## How to verify this work is correct

**Step 1:**
```bash
cd src/hub && cargo test --release
```
  - **Pass:** test result: ok. 70 passed; 0 failed. Includes dhcp::tests::two_machines_get_two_different_addresses, dhcp::tests::we_refuse_to_answer_where_a_router_exists, cable::tests::underscores_in_a_folder_name_are_left_alone and packaging_tests::every_packaging_recipe_names_this_version.
  - **Fail:** A compile error naming parse_leases or parse_arp means the cfg gates in net.rs were lost. A failure in every_packaging_recipe_names_this_version means a version string drifted between Cargo.toml, PKGBUILD, build-deb.sh and docs/HOW-TO.md.

**Step 2:**
```bash
Serve a temp folder containing only ok.txt, with a secret.txt in its parent, then: curl -s --path-as-is 'http://127.0.0.1:PORT/../secret.txt' and the percent-encoded form '%2e%2e%2fsecret.txt'
```
  - **Pass:** Both return 'forbidden'. A plain GET of /ok.txt?dl=1 returns the file contents, proving the check is not refusing everything.
  - **Fail:** The contents of secret.txt. That is the exact defect this merge exists to keep out; it was reproduced against the 0.8.1 rewrite, up to and including reading C:\Windows\win.ini.

**Step 3:**
```bash
printf 'POST /note HTTP/1.1\r\nHost: x\r\nContent-Length: 2000000000\r\n\r\n' | nc 127.0.0.1 PORT, then request a file again
```
  - **Pass:** The server responds and remains alive for the subsequent request.
  - **Fail:** The process aborting. The crate is built with panic = "abort", so an unclamped vec![0u8; content_length] is a one-packet remote kill.

**Step 4:**
```bash
./hub doctor on a machine with a cable plugged in and no router
```
  - **Pass:** 'hub 0.9.0'; a cable line naming the adapter and its negotiated speed; a chunk size consistent with tune::chunk_for; and 'cable addresses  this looks like a bare cable, so addresses can be given out'.
  - **Fail:** 'not offered here, which is correct on a network with a router' while genuinely on a bare cable. That was the regression caused by treating the guessed 169.254.x.1 gateway as real, and is covered by the assertion in we_refuse_to_answer_where_a_router_exists.

**Step 5:**
```bash
Run hub with no arguments
```
  - **Pass:** A four-item home menu; entry two is the cable sender; entry four is Checkup. Selecting the cable sender shows a two-row form with no wifi name, password or channel row.
  - **Fail:** Editing the second row of the cable form writes into self.ssid, which would mean the cable arm of commit() is missing.

**Step 6:**
```bash
hub cable <folder> on one machine, hub cable-get on the other, joined by a CAT cable and given 30 seconds to settle
```
  - **Pass:** The receiver prints 'Found <name> at 169.254.x.y' and fetches each file. THIS STEP HAS NOT BEEN PERFORMED for 0.9.0 and is the highest-priority open item.
  - **Fail:** 'Nothing answered in 60 seconds' points at the beacon or a firewall; finding the peer but failing to list files points at the HTTP side; a malformed URL in the fetch loop points at the missing slash bug described under tried_and_abandoned.

**Step 7:**
```bash
On a Linux host: file ./hub && ./hub --version && ./hub doctor
```
  - **Pass:** 'ELF 64-bit LSB executable, x86-64, statically linked' and 'hub 0.9.0'. NOT YET PERFORMED.
  - **Fail:** Any dynamic-loader requirement, which would defeat the point of the musl build and break on distributions with a different glibc.


## Technical Debt

🔴 **HIGH** — The end-to-end cable path has unit tests for its parts but no integration test → Add a test that runs a beacon and find_peer against each other over loopback, and ideally a two-process harness in the existing bench/ directory. Until then, treat the headline feature as unproven for this release.
🟠 **MEDIUM** — The musl artifact is built with an out-of-tree linker configuration → The zig cc wrapper and the CARGO_TARGET_*_LINKER / -C link-self-contained=no flags live in a scratch directory, so the Linux build is not reproducible by anyone else. Commit a .cargo/config.toml or a GitHub Actions workflow that encodes it.
🟠 **MEDIUM** — dhcp.rs binds 0.0.0.0:67 and cannot tell which interface a request arrived on → safe_to_offer() guards this from the host side, which is sound but indirect. If std ever exposes it, or if a raw socket option is acceptable, prefer IP_PKTINFO to scope replies to the cable interface.
🟡 **LOW** — Request.requested (DHCP option 50) is parsed but never used → Either honour a client's requested address when it is free, which shortens reconnection, or drop the field. It is currently dead weight the compiler flags.
🟡 **LOW** — tune::reachable() returns None on all non-Windows platforms → Probe ufw/firewalld/nft where present. Reporting 'cannot tell' is honest but leaves Linux users without the diagnostic that is most useful on Windows.
🟡 **LOW** — Pre-existing dead code flagged by the compiler in page.rs, net.rs and term.rs → Six warnings predate this work. Remove or #[allow] them so a genuinely new warning is not lost in the noise.
