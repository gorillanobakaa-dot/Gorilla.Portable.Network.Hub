# 0.9.10 — developer notes

Written 2026-09-24 on the Windows laptop (ThinkPad L15 Gen 3, Intel AX201,
Windows 11). Two strands: a day of radio measurements, which turned up four
bugs, and a pass over every screen and page for somebody who has never used
the program. Each section: what was wrong or missing, how it was found, what
changed, where. The code comments at each change say the same at the place it
applies. Items marked **not yet seen working** are built and tested for what
can be tested, but the event they handle has not recurred since.

---

## 1. Windows' five-minute hotspot timeout (net.rs `WIN_HOTSPOT`)

**Found in `network.log`**: "network gone ... back after 2 s" at 5-minute
intervals whenever no phone was connected. Windows' Mobile Hotspot has a
"turn off when no devices are connected" setting, on by default.

**Measured before building:** `NetworkOperatorTetheringManager` has static
`IsNoConnectionsTimeoutEnabled`, `DisableNoConnectionsTimeout` and
`EnableNoConnectionsTimeout`. As an ordinary user, `DisableNoConnectionsTimeout()`
took effect without an administrator prompt. With it off, 7 minutes with no
client: no drop, address still present.

**Changed:** the `start` action disables the timeout when it is enabled, and
creates a note file (`%LOCALAPPDATA%\PortableNetworkHub\hotspot-timeout-was-on`,
path passed in `HUB_TIMEOUT_NOTE`). The `stop` action re-enables it only if
the note exists, then deletes the note. A file rather than memory because the
watchman, which stops the network after a crash or the window's X, is a
separate process; `arm_watchman` passes the same variable.

**Measured:** timeout ON; hub started: timeout OFF and the note present; hub
killed (as the X or a crash would): the watchman's stop put the timeout back ON
and removed the note. `network.log` records both transitions. The clean Stop
in the screen runs the same `stop` action; it was not separately exercised.

## 2. The guard: stop, then start (net.rs `guard_hotspot`)

**Seen once**, after the hotspot services had been switched off and on for the
not-ready screenshots: Windows reported the hotspot `On` and accepted every
restart for about two minutes, but the adapter never received 192.168.137.1.
A full stop and start of the hub brought it up at once.

**Changed:** `empty_starts` counts accepted starts that produced no address;
after two, the guard runs `stop`, waits 2 s, then starts. Logged as "still no
address after two starts". **Not yet seen working**: the state has not
recurred. Note that `stop` also restores the five-minute timeout (section 1),
and the following `start` turns it off again; the note file makes that
consistent.

## 3. `hub serve --channel` hung (serve.rs `run`)

The `--channel` arm never advanced `i`, so the argument loop spun forever
before printing anything. In the tree since 2026-08-25 (`dbe5559`), and the
README's own Linux example uses the flag. Fixed with `i += 2`; checked with
`hub serve . --channel 6 --port 18999`, which now starts.

## 4. Broken-off downloads were invisible (serve.rs `send_file`)

A 10.6 GB download to a phone made Windows count 14.1 GB out; the hub's window
said nothing, because it printed only completed sends. The phone's download
manager had re-fetched about 2.8 GB. `send_file` now prints `<peer> broke off
after <done> of <len> bytes (from byte <start>) in <s>s = <MB/s>` when a write
fails, unless the screen is drawing (QUIET).

## 5. `hub serve` printed unreachable addresses (serve.rs)

While the hotspot's address was still arriving, `to_tell` fell back to every
local address: the phone network's 172.22.x and a 169.254 one, neither
reachable from the hotspot. On Windows, with a hotspot, it now prints
192.168.137.1 (Windows' ICS scope address) with a line saying it works in a few
seconds.

## 6. The class page (page.rs `class_page`, `files_frame`)

Rewritten for a child reading it for the first time:

- numbered sections (`<h2>1. Files from your teacher`, `2. Send your work`,
  `3. Send a note`), each with a one-line `.hint` saying what its buttons do;
- `SEND_SCRIPT`: the hand-in form is sent with `XMLHttpRequest` and
  `FormData`, the button shows `SENDING... N% - KEEP THIS PAGE OPEN` from
  `upload.onprogress`, and `onload` follows `responseURL` (the server's 303 to
  `/?done=...`). No FormData or XHR: the plain post, as before. SEND with
  nothing chosen is answered on the page (`#sendmsg`). `responseURL` missing
  (very old WebViews): goes to `/`, never claims success;
- result boxes for every `done` tag, green `.done` or red `.bad`, each saying
  what happened and what next (`cantsave`: "Nothing is lost");
- "Where do the files I GET go?" in a `<details>`;
- the sign-in-window escape moved into `<details class=escape>` with the
  summary *Tapping Choose files does nothing?* Open, it told every browser it
  was the sign-in window; the page cannot reliably tell the Android captive
  WebView from Chrome, the child can;
- `input,textarea{box-sizing:border-box}`: the name box overflowed a 375 px
  screen;
- the file frame is 65vh with a border, and the hint says it scrolls.

Tests: `the_page_explains_itself_and_every_result` (sections, script, every
tag has a box, a failure says nothing was lost); the name-first test now
checks for the form's `action` instead of a heading that was renamed. Checked
in Edge at 375 px: name, sections, a 3 MB send through the XHR path landing
byte-exact in `waiting/`, the empty-send message.

## 9. The Windows bench (bench/)

New, for measuring the radio on Windows, where `transfer-watch.py`'s `/sys`
and `iw` do not exist:

| file | does |
|---|---|
| `transfer-watch-windows.py` | per-second psutil sampler of the hotspot adapter (found by 192.168.137.1), CPU, hub.exe, power; CSV, summary, SVG. The single best second is not reported: Windows' counters update in bursts (one second read 407 Mbit/s on a 287 Mbit/s link) |
| `phone-speedtest.html` | served by the hub; N Range requests into memory on the phone; counts exact payload bytes |
| `download-meter.py` | N Range requests from Python; software ceiling on loopback |
| `console-read.cs` | reads a console window's text by PID (`AttachConsole`, `ReadConsoleOutputCharacterW`) |
| `screenshot-tour.ps1` 1.2.0 | names pictures from `hub --version`; adds the Start row and the help page; sends PowerShell's module cache to TEMP (with USERPROFILE moved it was written into the lesson folder as `Microsoft\Windows\PowerShell`) |
| `screenshot-phone-page.py` 2.0.0 | six phone pictures; slows the upload with CDP `Network.emulateNetworkConditions` to photograph the progress |

Results: [bench/RESULTS-WINDOWS.md](../bench/RESULTS-WINDOWS.md). In short:
best 30 s 191 Mbit/s against a 286.8 Mbit/s link (66.6%), one connection best,
Throughput Booster no effect, software ceiling 756 MB/s on loopback. 85% was
not reached; the section "Not yet tried" lists what is left.
