# 0.10.0 — developer notes

Written 2026-09-24 on the Windows laptop. Three features, one design each:
two-way messages (chat.rs), private help with a locked record (adult.rs,
record.rs, crypto.rs), and the children's pages in six languages (i18n.rs).
The decisions behind the private help were the owner's (receiver chosen at
the start; every word kept, locked; an optional second adult; English plus
French, Swahili, Portuguese, Dari, Pashto). Items marked **not yet** have not
been done, and are listed at the end.

---

## 1. Messages (chat.rs, page.rs, serve.rs, tui.rs)

**Model.** One list of `Msg { id, at, key, label, from_child, private, kind,
text, seen }`. `key` is `serve::device_key(ip)`: the device's tag where
there is one (`tag:xxxx`), so a phone that gets a new address keeps its
conversation, as names and blocks already do. Ordinary and private messages
are separate conversations with the same key (`private` flag); nothing ever
crosses between them. At most 200 per conversation in memory; the lesson's
Stop clears memory (`chat::clear`).

**Transport.** The phone polls `GET /talk?p=0|1&v=<version>` every 4 s. Each
conversation has a version bumped on every change a phone should see; the
answer is `204` when unchanged, or `<version>\n<rendered conversation>`. A
request that ends at once never holds a worker. Websockets or long polling
would each hold one of a fixed pool (16 workers on a two-core laptop; the
project measured this countdown once, serve.rs `IO_TIMEOUT`). Polling stops
while the page is hidden. Sending is `POST /talk` (token, kind, p, text);
with `X-Hub: 1` the answer is one word (`sent`, `empty`, `toofast`), without
it a 303 back (`/#talk` or `/page2`), so a phone without script still works.
Old pages' `/note` still lands, and joins the conversation.

**Rules.** Tokens make a retry land once; eight messages a minute per device;
**a private one-tap (need, yes, later, no) is never refused for speed**.
2,000 characters per message.

**Seen.** Showing a conversation on the phone (`child_saw`) marks the adult's
messages seen; the adult opening one (`adult_opened`, also called from
`draw()` while a conversation is on screen) marks the child's.

**Teacher.** `Screen::Messages` lists `message_rows()`: private
conversations first (only when the teacher receives them, words replaced by
"(open to read)" or "ASKED TO TALK"), then ordinary ones, then every child
on the network without one, so the teacher can write first. `Screen::Thread`
takes typing directly into `draft`; Enter sends (`adult_says`), Tab in a
private conversation sends the quiet request, Up/Down scroll. The sending
screen shows counts only, never words; with a trusted adult receiving, not
even the private count.

Tests: `chat::tests` (5), `page::tests::a_child_and_the_teacher_talk_through_the_page`,
`tui::tests::the_teacher_reads_and_answers_a_child` (typing q types q).

## 2. Private help (page.rs, adult.rs, serve.rs)

**The child's page** is `/page2`, titled like the class page, `no-store`,
`referrer: no-referrer`. HIDE and the HELP door navigate with
`location.replace`, so no history step leads back. `talk_fragment` puts the
adult's open request (`chat::open_request`) at the **bottom** of the
conversation, where it is scrolled to: at the top it was half hidden
(seen in the flow test's pictures). The class page's HELP door shows a dot
when the adult has written or asked; nothing else changes.

**The adult's page** is `/adult`, routed **before** the pause check: a
teacher pausing the trusted adult's phone must not cut a child's help off.
Sign-in is `record::who_is(password)` (the same PBKDF2 as unlocking);
success sets `hubadult=<random 128-bit token>; Path=/adult; HttpOnly;
SameSite=Strict`, 12 h, forgotten at Stop. Five wrong passwords from one
address in five minutes lock that address out for the rest of the window.
Conversation view: an iframe (`/adult/frame`, refresh 5 s) above the answer
form, so typing is never lost to a refresh.

**Bug found by the flow test, fixed.** The conversation key was
URL-encoded into the forms' hidden fields; the browser encoded it again, and
every answer and request went to a conversation that did not exist. Hidden
fields now carry the HTML-escaped key, links the URL-encoded one.

**Switching on.** Start screen rows 4 to 6 (wifi mode): receiver (Enter
cycles nobody / teacher / trusted adult), the password (stars while typed),
the second adult's password. `start_private_help()` runs after the server
starts: under 8 characters, private help stays off and the sending screen says
why; otherwise `record::start` and `chat::set_receiver`. `forget_session`
switches it off, forgets the record key, signs the adults out. From the
command line: `hub serve ... --help-password <pw> [--second-password <pw>]`
(receiver: trusted adult).

Tests: `page::tests::private_help_is_off_until_locked_and_stays_off_the_ordinary_page`,
`tui::tests::private_words_never_show_on_the_teachers_list`,
`tui::tests::private_help_needs_a_lock_and_ends_with_the_lesson`,
`adult::tests::only_the_right_password_signs_in_and_guessing_is_stopped`.

## 3. The locked record (record.rs, crypto.rs)

**crypto.rs**, no crates: ChaCha20 (RFC 8439), HMAC-SHA256 (RFC 2104) on the
existing sha256.rs, PBKDF2-HMAC-SHA256 (one block). `seal` is
encrypt-then-MAC with keys derived from the one key by HMAC ("gorilla record:
encrypt" / "...: seal"), a random 12-byte nonce each time from
`net::random_bytes` (`/dev/urandom`, `RtlGenRandom`), and a 32-byte tag;
`open` checks the tag in constant time before decrypting. Tests: RFC 4231
case 1, the common "password"/"salt" PBKDF2 values at 1, 2 and 4096 rounds,
the full RFC 8439 section 2.4.2 text; all confirmed independently with
Python's `cryptography` 50.0.1 and `hashlib`.

**record.rs.** One file per lesson, `private-record-<stamp>.gpr` in the
received folder:

```
GORILLA PRIVATE RECORD 1
SLOT <name b64> <salt b64> <iterations> <seal(pbkdf2(pw, salt), data_key) b64>
E <seal(data_key, "time\tlabel\tby\tkind\ttext") b64>
```

200,000 rounds: 322 ms per guess on the i7-1255U (measured by the test
`unlocking_takes_long_enough_to_slow_guessing`, which fails under 20 ms).
Each entry names **who wrote it**: child, teacher, trusted adult or second
adult. With two adults, "an adult" would not say which, and the record exists
partly so that an adult cannot misuse the channel unseen. `hub
private-record [dir]` asks the password and prints every record it opens.
Windows PowerShell puts a byte-order mark before piped text; the command
strips it (found when a correct password opened nothing through a pipe).

Tests: either adult opens it and nobody else does, no words or names in the
clear, nothing written after Stop, a changed entry is reported rather than
trusted.

**Said out loud:** the record does not stop deletion, and nothing protects the
words on the air (plain http, WPA2 with a password the whole class has).

## 4. Six languages (i18n.rs, page.rs)

`t(lang, "English sentence")` looks the sentence up in `TABLE` (English,
then French, Swahili, Portuguese, Dari `prs`, Pashto `ps`); missing falls
back to English. `tf` fills `{n}`, `{name}`, `{size}`. The choice is
`?lang=xx`, kept per device key; the name page offers the six at the top, the
class page at the foot. `html_open` sets `lang` and `dir="rtl"` for Dari
(`fa-AF`) and Pashto. Layout uses `margin-inline-*` and
`padding-inline-start` so it turns round with the text; the viewer's and the
HIDE button's arrows flip. The scripts take their words from `data-`
attributes rendered in the child's language. HELP is always "HELP" plus the
local word. The teacher's screens and the adult's page stay English.

Tests: every row complete and keeping its placeholders; **every `t(l, "...")`
in page.rs has a row** (the test reads page.rs with `include_str!`, found 89,
and fails if it finds fewer than 60, so it cannot pass by reading nothing);
right-to-left for Dari and Pashto.

**The translations are AI drafts, not checked by native speakers.** Said in
the module, the guide and the release notes.

## 5. Bench

`bench/chat-flow-test.py` (Playwright, Edge): a child's phone and the adult's
phone in separate sessions; 13 checks from the first message to HIDE. It
chooses English explicitly: every session on the test laptop is 127.0.0.1, so
a language chosen by an earlier run carries over. `bench/screenshot-tour.ps1`
1.3.0 sets private help to a trusted adult with a demo password, runs the flow
test against the tour's hub, and photographs Messages and a conversation.
